Functions vs Agent Sandboxes

A function serves anyone's request from a shared pool and forgets it. An agent sandbox belongs to one user's conversation, keeps its working state while it lives, and puts anything that must last somewhere outside.

Same isolation technology on both sides (Firecracker runs Lambda and OpenSandbox's Fast Sandbox); the difference is who owns the machine and how long it lives. On phones, scroll the diagram sideways.

Dedicated, not pooled

A sandbox serves one user's session for its whole life. Warm pools exist to make creation fast, but once a session claims a sandbox it is that session's alone. Function workers are interchangeable and shared across everyone's requests.

What must last goes outside

Pause/resume snapshots memory and disk, so a planned pause is covered. Anything that must survive a crash or a kill, like files or conversation history, belongs on a volume, in git or an object store. Credential Vault is held in memory: after a Kubernetes pause/resume it starts empty and is re-created.
